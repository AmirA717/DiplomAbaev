3.1 Ручное тестирование пользовательской части системы

3.1.1 Проверка сценария регистрации пользователя

При выполнении проверки функциональности регистрации новой учетной записи была произведена переходиия на страницу входа приложения (URL: http://localhost:3000). На данной странице находится форма аутентификации со ссылкой на страницу регистрации. Нажатие на элемент "Создать аккаунт" или переход по ссылке регистрации перемещает пользователя на страницу регистрации (URL: http://localhost:3000/register).

На странице регистрации расположена форма с обязательными полями: электронная почта, пароль, подтверждение пароля, имя и фамилия. Форма содержит кнопку "Зарегистрироваться" для отправки данных на сервер.

При вводе корректных данных (электронная почта в формате user@example.com, пароль соответствующий требованиям безопасности) и нажатии кнопки отправки система выполняет следующие действия: происходит отправка запроса на серверный API, сервер проверяет уникальность электронной почты и валидность входных параметров, при успешной обработке в базе данных создается новая запись пользователя с зашифрованным паролем.

Проверка подтвердила, что система корректно обрабатывает граничные случаи: при оставлении полей пустыми форма отображает сообщение об ошибке валидации; при попытке регистрации с существующей электронной почтой система возвращает ошибку о том, что адрес уже зарегистрирован; при вводе паролей не соответствующих требованиям безопасности система выводит сообщение о необходимости укрепления пароля. После успешной регистрации пользователь автоматически перенаправляется на страницу входа или сразу в приложение.

3.1.2 Проверка сценария авторизации пользователя

Для проверки функции авторизации была открыта страница входа приложения (URL: http://localhost:3000/login). На этой странице расположена форма входа с полями для ввода электронной почты и пароля, а также кнопка "Войти" и ссылка на страницу регистрации.

При вводе корректных учетных данных зарегистрированного пользователя (электронная почта и соответствующий ей пароль) и нажатии кнопки входа система выполняет отправку данных на сервер. Сервер проверяет наличие пользователя в базе данных, сравнивает введённый пароль с сохранённым хешем, и при совпадении генерирует JWT токен для аутентификации текущей сессии. После успешной авторизации приложение сохраняет токен в локальном хранилище браузера и осуществляет перенаправление пользователя на главную страницу приложения.

При вводе неверного пароля или несуществующей электронной почты система отображает сообщение об ошибке аутентификации без раскрытия деталей о том, какие именно параметры являются неверными. Это обеспечивает безопасность системы путём предотвращения перебора учетных данных.

После успешного входа элементы интерфейса, требующие аутентификации (такие как ссылки на профиль, список викторин и личную статистику), становятся доступными для взаимодействия.

3.1.3 Проверка просмотра списка учебных тем

После входа в систему пользователь получает доступ к главной странице приложения (URL: http://localhost:3000/topics). На этой странице отображается список опубликованных образовательных тем в виде карточек. Каждая карточка темы содержит название темы, краткое описание, и кнопку для перехода к полному просмотру темы.

При проверке функциональности список тем загружается при открытии страницы и корректно отображает данные, полученные с сервера. Система поддерживает пагинацию для эффективного отображения большого количества тем. При нажатии на карточку темы или кнопку "Узнать больше" пользователь перемещается на страницу детального просмотра выбранной темы.

Проверка подтвердила, что система корректно обрабатывает состояния: при загрузке данных отображается индикатор прогресса; при отсутствии доступных тем отображается соответствующее сообщение; при наличии ошибки сервера пользователю выводится информационное сообщение об ошибке.

3.1.4 Проверка просмотра деталей темы и связанных материалов

При переходе на страницу конкретной темы (URL: http://localhost:3000/topics/{id}) пользователь получает полную информацию о теме: название, развёрнутое описание, содержание материала, дату создания и последнего обновления.

На этой же странице отображаются разделы, связанные с темой: список учебных материалов (статьи, видеоматериалы, ссылки на внешние ресурсы), доступные викторины по данной теме и мини-игры для практического закрепления знаний. Каждый материал представлен в виде элемента с названием, типом материала, ссылкой на источник и кратким описанием.

При нажатии на материал система открывает соответствующий ресурс: статьи отображаются внутри приложения, видеоматериалы проигрываются во встроенном плеере, ссылки на внешние ресурсы открываются в новой вкладке браузера. Проверка подтвердила, что все ссылки на материалы функционируют корректно и ведут на указанные ресурсы без ошибок навигации.

3.1.5 Проверка запуска и прохождения викторины

Для проверки функциональности викторин пользователь выбирает викторину из списка доступных викторин по теме и нажимает кнопку "Начать викторину". При этом происходит переход на страницу викторины (URL: http://localhost:3000/quizzes/{id}), где отображаются общие информация о викторине: название, описание, количество вопросов, максимальный балл, проходной балл.

На этой странице находится кнопка "Запустить попытку" для инициирования начала прохождения викторины. При нажатии на кнопку система создает запись о попытке в базе данных и перенаправляет пользователя на страницу с первым вопросом викторины.

На странице прохождения викторины (URL: http://localhost:3000/attempts/{attemptId}) отображаются: текущий вопрос викторины, варианты ответов (в зависимости от типа вопроса это могут быть переключатели для единственного выбора или флажки для множественного выбора), номер текущего вопроса и общее количество вопросов, кнопки "Предыдущий вопрос" и "Следующий вопрос" для навигации.

Проверка функциональности выбора ответов подтвердила следующее: система позволяет пользователю выбрать один или несколько вариантов ответа в зависимости от типа вопроса; при попытке перейти к следующему вопросу без выбора ответа система отображает сообщение об ошибке и блокирует переход; выбранные ответы сохраняются при навигации между вопросами.

После прохождения всех вопросов пользователь нажимает кнопку "Завершить викторину", что инициирует отправку всех ответов на сервер. Сервер выполняет проверку правильности ответов путем сравнения с эталонными значениями, рассчитывает итоговый балл, определяет статус прохождения (пройдена/не пройдена) на основе проходного балла и сохраняет результаты в базе данных.

После завершения викторины система отображает страницу результатов (URL: http://localhost:3000/results/{attemptId}) со следующей информацией: количество набранных баллов и максимальный возможный балл, процент правильных ответов, статус прохождения викторины (пройдена/не пройдена), для каждого вопроса отображается: выбранный пользователем ответ, правильный ответ (если выбран неправильно), объяснение к вопросу и количество полученных баллов.

Проверка показала, что система корректно рассчитывает баллы, обновляет личную статистику пользователя (количество пройденных викторин, сумму набранных баллов, средний балл), и предоставляет возможность повторного прохождения викторины или возврата к списку тем.

3.1.6 Проверка функциональности мини-игр

При открытии страницы темы пользователь может выбрать доступные мини-игры для практического закрепления знаний. В системе реализованы две основные мини-игры: игра по распознаванию фишинга и игра по оценке надежности пароля.

Для игры по распознаванию фишинга при нажатии на элемент игры система перемещает пользователя на страницу игры (URL: http://localhost:3000/games/phishing-detector). На этой странице отображаются сценарии потенциального фишинга (электронные письма, сообщения, веб-сайты) с просьбой определить, является ли сценарий фишингом или нет.

Пользователь анализирует представленный сценарий и нажимает одну из двух кнопок: "Это фишинг" или "Это легитимно". После выбора система отображает результат (правильно/неправильно), предоставляет объяснение с указанием признаков фишинга в данном сценарии и выдает баллы за правильный ответ. После завершения всех сценариев игра отображает финальный результат: количество правильно распознанных фишинговых сценариев, общий балл и рекомендации.

Для игры по оценке надежности пароля при открытии игры (URL: http://localhost:3000/games/password-strength) пользователь получает возможность вводить пароли и оценивать их надежность. При вводе пароля в текстовое поле система в реальном времени (по мере ввода символов) вычисляет уровень надежности пароля на основе критериев: длина пароля, наличие строчных букв, прописных букв, цифр и специальных символов.

Система отображает визуальный индикатор уровня надежности (например, полоса с цветовой шкалой: красный для слабого пароля, желтый для среднего, зелёный для надежного) и текстовое описание уровня. При выборе режима "Генератор паролей" система предоставляет возможность сгенерировать надежный пароль с учётом выбранных параметров (длина, включение специальных символов и т.д.).

Проверка показала, что вычисление уровня надежности выполняется корректно, индикатор обновляется при изменении ввода, рекомендации формируются в соответствии с выявленными недостатками в пароле, и результаты игры (пройденные задания, полученные баллы) сохраняются в базе данных для внесения в личную статистику пользователя.

3.1.7 Проверка функциональности профиля пользователя

Для доступа к странице профиля пользователь нажимает на иконку профиля или выбирает пункт меню "Мой профиль" (URL: http://localhost:3000/profile). На этой странице отображаются текущие данные пользователя: электронная почта, имя, фамилия, биография (если заполнена), аватар (если загружен), дата создания аккаунта.

На странице профиля находится кнопка "Редактировать профиль", при нажатии на которую либо открывается отдельная страница редактирования, либо форма становится редактируемой. В режиме редактирования пользователь может изменять следующие поля: имя, фамилия, биография, загрузить новый аватар.

При попытке изменить электронную почту на уже зарегистрированный адрес система отображает ошибку валидации. После внесения изменений и нажатия кнопки "Сохранить" система отправляет обновленные данные на сервер, который выполняет валидацию и сохраняет изменения в базе данных. При успешном сохранении пользователь видит сообщение об успехе, и данные на странице профиля обновляются отражая внесённые изменения.

Проверка подтвердила, что изменения данных профиля сохраняются корректно, при обновлении страницы данные остаются изменёнными, система корректно обрабатывает загрузку файлов для аватара (проверка формата файла, размера) и отображает загруженное изображение в профиле.

3.1.8 Проверка функциональности статистики и достижений пользователя

Для просмотра личной статистики пользователь переходит на страницу статистики (URL: http://localhost:3000/stats). На этой странице отображается следующая информация: общее количество пройденных попыток викторин, количество успешно пройденных викторин, текущее количество набранных очков, средний балл по всем викторинам, количество пройденных тем, количество завершённых мини-игр.

На странице также представлена информация о прогрессе по отдельным темам в виде таблицы или графиков, показывающая для каждой темы: название темы, количество пройденных викторин по теме, общее количество викторин по теме, средний балл по этой теме.

Для просмотра достижений пользователь выбирает соответствующий раздел (URL: http://localhost:3000/achievements). На странице достижений отображаются полученные награды и достижения пользователя: иконка достижения, название, описание, дата получения. Достижения, которые пользователь еще не получил, отображаются в затемненном виде с информацией об условиях их получения.

Проверка функциональности подтвердила, что статистика обновляется сразу после завершения викторины или мини-игры, значения рассчитываются корректно, достижения выдаются пользователю при выполнении условий их получения, информация о достижениях отображается корректно.

3.1.9 Проверка функциональности административной панели

Для доступа к административной панели пользователь с ролью администратора переходит по адресу http://localhost:3000/admin. При попытке входа в административную панель от учетной записи обычного пользователя система отображает сообщение об ошибке доступа и перенаправляет на главную страницу.

На главной странице административной панели отображается информационная сводка: количество зарегистрированных пользователей, количество созданных тем, количество активных пользователей, статистика по викторинам.

3.1.9.1 Проверка управления темами в административной панели

Администратор переходит в раздел управления темами (URL: http://localhost:3000/admin/topics). На этой странице отображается список всех тем (как опубликованных, так и черновиков) в виде таблицы с колонками: название темы, дата создания, статус публикации, действия (редактирование, удаление, просмотр).

Администратор может нажать кнопку "Создать новую тему" для добавления новой образовательной темы. При нажатии открывается форма для создания темы с полями: название темы, описание, содержание материала, установка статуса публикации (опубликована/черновик).

При нажатии на кнопку "Редактировать" рядом с темой администратор может изменять все параметры темы, включая изменение статуса публикации. При попытке опубликовать тему с пустыми обязательными полями система отображает сообщение об ошибке валидации.

Проверка подтвердила, что при изменении статуса публикации на "Опубликована" тема становится доступной для просмотра обычными пользователями; при статусе "Черновик" тема не отображается в списке тем на главной странице приложения для обычных пользователей (но остается видна администратору); при удалении темы система запрашивает подтверждение для предотвращения случайного удаления.

3.1.9.2 Проверка управления викторинами в административной панели

Администратор может перейти в раздел управления викторинами (URL: http://localhost:3000/admin/quizzes). На этой странице отображается список всех викторин в виде таблицы.

Администратор может нажать кнопку "Создать новую викторину" для добавления викторины. При нажатии открывается форма с полями: название викторины, описание, связанная тема, максимальный балл, проходной балл, статус публикации.

При нажатии на кнопку "Редактировать викторину" администратор может изменять параметры викторины. Особое внимание уделяется разделу управления вопросами: администратор может добавлять новые вопросы, редактировать существующие вопросы (изменение текста вопроса, типа вопроса, вариантов ответов), удалять вопросы, переупорядочивать порядок вопросов в викторине.

При добавлении вопроса администратор указывает: текст вопроса, тип вопроса (единственный выбор или множественный выбор), варианты ответов с указанием правильных вариантов, объяснение к вопросу, количество баллов за вопрос.

Проверка показала, что система корректно сохраняет все вопросы и ответы, при изменении параметров вопроса обновляются данные в базе, при удалении вопроса система запрашивает подтверждение.

3.1.9.3 Проверка просмотра статистики пользователей в административной панели

Администратор может перейти в раздел статистики (URL: http://localhost:3000/admin/stats). На этой странице отображается общая статистика по системе: общее количество пользователей, количество активных пользователей (вошедших за последние 7 дней), количество завершенных попыток викторин, средний балл по системе, популярные темы (темы, которые изучают больше пользователей).

Администратор также может просмотреть детальную статистику по отдельным пользователям (URL: http://localhost:3000/admin/users). На этой странице отображается список пользователей в виде таблицы с информацией: электронная почта пользователя, имя, фамилия, дата регистрации, количество пройденных викторин, средний балл, дата последней активности.

При нажатии на пользователя администратор может просмотреть подробную статистику конкретного пользователя: все пройденные попытки викторин с датами, баллами, статусами, достижения пользователя, активность по темам.

Проверка подтвердила, что все показатели статистики рассчитываются корректно, данные обновляются в реальном времени, статистика соответствует информации, хранящейся в базе данных.

3.1.10 Заключение по результатам ручного тестирования

Ручное тестирование всех компонентов пользовательской части системы платформы кибер-обучения подтвердило корректность функционирования следующих аспектов:

1. Правильность обработки входных данных: система корректно валидирует данные, отображает сообщения об ошибках валидации, предотвращает внесение некорректных данных.

2. Корректность логики приложения: переходы между экранами выполняются без ошибок, сохранение данных происходит корректно, личная статистика обновляется в соответствии с действиями пользователя.

3. Безопасность системы: система требует аутентификации для доступа к защищённым ресурсам, пароли хранятся в виде хешей, административная панель доступна только пользователям с ролью администратора.

4. Полнота функциональности: все основные сценарии использования платформы (регистрация, обучение, прохождение викторин, мини-игры, просмотр статистики) функционируют как ожидается.

5. Обработка граничных случаев: система корректно обрабатывает ошибочные ситуации (пустые поля, некорректные данные, повторная регистрация), отображая информативные сообщения об ошибках.

Проведённое ручное тестирование позволяет рекомендовать пользовательскую часть системы к развертыванию в среде производства с высокой степенью уверенности в её стабильности и корректности функционирования.
