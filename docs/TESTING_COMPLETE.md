## 3.1 План тестирования

### 3.1.1 Типы и подходы тестирования

**Используемые методики:**
1. **Ручное функциональное тестирование (Черный ящик)** - проверка функциональности без анализа внутреннего кода
2. **Ручное тестирование API** - проверка серверных конечных точек через Swagger/Postman
3. **Автоматизированное модульное тестирование (Unit-тесты)** - проверка отдельных компонентов кода
4. **Граничное тестирование** - проверка поведения на граничных значениях и исключительных ситуациях

### 3.1.2 Возможные ошибки пользователя и сценарии тестирования

Система разработана с учётом следующих типичных ошибок пользователей:

- **Ошибки при вводе данных:** пустые поля, некорректный формат, значения за пределами допустимого диапазона
- **Ошибки валидации:** пароли не соответствующие требованиям, email в неправильном формате, дублирующиеся учетные данные
- **Ошибки при использовании приложения:** попытка доступа к защищённым ресурсам без авторизации, неправильная последовательность операций
- **Граничные случаи:** очень длинные строки, спецсимволы, пустые результаты, несуществующие ресурсы
- **Условия ошибок сервера:** потеря соединения, таймауты, ошибки базы данных
