## Введение

Настоящий документ содержит описание процедур ручного тестирования API платформы кибер-обучения. На этапе тестирования проводится проверка работоспособности серверного приложения на совокупности репрезентативных тестовых данных, включая нормальные режимы эксплуатации и граничные случаи.

Целями ручного тестирования являются:
- Проверка функциональной корректности обработки входных данных;
- Валидация промежуточных вычислений и преобразований данных;
- Верификация формирования правильных выходных данных;
- Контроль соответствия HTTP статус-кодов ожидаемым значениям;
- Проверка обработки ошибочных ситуаций;
- Валидация механизмов аутентификации и авторизации.

### Область применения

Данное руководство предназначено для инженеров контроля качества (QA), разработчиков и администраторов системы, проводящих тестирование серверного API компонента системы до развертывания в продуктивной среде.

## Подготовка к тестированию

### 1. Запуск приложения локально

#### Вариант 1: Без Docker (развитие)

```bash
# 1. Перейти в директорию проекта
cd cyber-education-backend

# 2. Установить зависимости
npm install

# 3. Сгенерировать Prisma клиент
npx prisma generate

# 4. Выполнить миграции БД
npx prisma migrate dev

# 5. Заполнить БД тестовыми данными
npm run prisma:seed

# 6. Запустить приложение в режиме разработки
npm run start:dev
```

Приложение будет доступно по адресу: **`http://localhost:3000`**

#### Вариант 2: С помощью Docker Compose

```bash
# Перейти в директорию проекта
cd cyber-education-backend

# Построить образы и запустить контейнеры
docker compose up --build

# Выполнить миграции и заполнить БД (в отдельном терминале)
npm run prisma:seed:docker
```

Приложение будет доступно по адресу: **`http://localhost:3000`**

### 2. Установка Postman

1. Загрузить Postman с официального сайта: https://www.postman.com/downloads/
2. Установить приложение согласно инструкциям ОС
3. Запустить Postman

### 3. Доступ к Swagger документации

После запуска приложения документация автоматически генерируется и доступна по адресу:

**`http://localhost:3000/docs`**

Здесь можно:
- Просмотреть все доступные endpoints
- Ознакомиться с требуемыми параметрами
- Изучить структуру ответов
- Скопировать примеры запросов

## Тестовые сценарии

### Сценарий 1: Регистрация пользователя

#### Описание
Проверка функции регистрации новой учетной записи пользователя в системе с валидированием входных данных.

#### Предусловия
- Приложение запущено и доступно по адресу `http://localhost:3000`
- Postman установлен и открыт
- Интернет-соединение активно

#### Инструкция по воспроизведению

**Шаг 1: Создать новый запрос в Postman**

1. Открыть Postman
2. Нажать кнопку **"+"** для создания новой вкладки (или Ctrl+T)
3. Выбрать метод **POST**
4. В поле адреса (URL) ввести: `http://localhost:3000/auth/register`

**Скриншот: Создание POST запроса**
```
┌─────────────────────────────────────────────────────────────────┐
│ POST  http://localhost:3000/auth/register                   [Send]
└─────────────────────────────────────────────────────────────────┘
```

**Шаг 2: Установить заголовки**

1. Перейти на вкладку **"Headers"**
2. Добавить или убедиться, что присутствует заголовок:
   - **Key:** `Content-Type`
   - **Value:** `application/json`

**Скриншот: Раздел Headers**
```
┌─────────────────────────────────────────────────────────────────┐
│ Headers                                                          │
├─────────────────────────────────────────────────────────────────┤
│ ☑ Content-Type    application/json                              │
└─────────────────────────────────────────────────────────────────┘
```

**Шаг 3: Добавить тело запроса (Body)**

1. Перейти на вкладку **"Body"**
2. Выбрать опцию **"raw"**
3. В выпадающем списке справа убедиться, что выбран тип **"JSON"**
4. В текстовое поле ввести следующий JSON:

```json
{
  "email": "testuser@example.com",
  "password": "SecurePassword123!",
  "firstName": "Иван",
  "lastName": "Петров"
}
```

**Скриншот: Раздел Body с JSON**
```
┌─────────────────────────────────────────────────────────────────┐
│ Body  │ Headers │ Cookies │ Pre-request Script │ Tests          │
├─────────────────────────────────────────────────────────────────┤
│ ● raw  ○ form-data  ○ urlencoded  [JSON ▼]                      │
├─────────────────────────────────────────────────────────────────┤
│ {                                                                │
│   "email": "testuser@example.com",                              │
│   "password": "SecurePassword123!",                             │
│   "firstName": "Иван",                                          │
│   "lastName": "Петров"                                          │
│ }                                                                │
└─────────────────────────────────────────────────────────────────┘
```

**Шаг 4: Отправить запрос**

1. Нажать кнопку **"Send"** (синяя кнопка в правом верхнем углу)
2. Дождаться ответа от сервера (обычно 1-2 секунды)

#### Ожидаемый результат

**HTTP Статус:** `201 Created`

**Тело ответа:**
```json
{
  "id": 1,
  "email": "testuser@example.com",
  "firstName": "Иван",
  "lastName": "Петров",
  "role": "USER",
  "createdAt": "2026-05-13T10:30:00.000Z"
}
```

**Что необходимо заскринить:**
1. ✓ URL запроса с методом POST
2. ✓ Содержимое вкладки Headers (Content-Type: application/json)
3. ✓ Содержимое вкладки Body с JSON данными
4. ✓ HTTP статус 201 Created
5. ✓ Тело ответа в разделе Response

### Сценарий 2: Вход пользователя и получение JWT токена

#### Описание
Проверка функции аутентификации пользователя с выдачей JWT токена для последующих аутентифицированных запросов.

#### Предусловия
- Приложение запущено
- Пользователь успешно зарегистрирован (см. Сценарий 1)
- Postman открыт

#### Инструкция по воспроизведению

**Шаг 1: Создать новый POST запрос**

1. В Postman создать новый запрос (Ctrl+T)
2. Выбрать метод **POST**
3. Ввести URL: `http://localhost:3000/auth/login`

**Шаг 2: Установить заголовки**

1. Перейти на вкладку **"Headers"**
2. Убедиться, что присутствует заголовок:
   - **Key:** `Content-Type`
   - **Value:** `application/json`

**Шаг 3: Добавить данные для входа в Body**

1. Перейти на вкладку **"Body"**
2. Выбрать **"raw"** и **"JSON"**
3. Ввести данные:

```json
{
  "email": "testuser@example.com",
  "password": "SecurePassword123!"
}
```

**Шаг 4: Отправить запрос**

Нажать **"Send"**

#### Ожидаемый результат

**HTTP Статус:** `200 OK`

**Тело ответа:**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpZCI6MSwiaWF0IjoxNjI2MzA1ODAwLCJleHAiOjE2MjY5MTA2MDB9.abcdef123456...",
  "user": {
    "id": 1,
    "email": "testuser@example.com",
    "firstName": "Иван",
    "lastName": "Петров",
    "role": "USER"
  }
}
```

**Действия после получения токена:**

1. **Сохранить токен** для использования в последующих запросах
   - Скопировать значение поля `access_token` из ответа
   - Сохранить его в текстовом редакторе или использовать переменные Postman

2. **Использовать токен в Postman для защищенных endpoints**
   - В последующих запросах перейти на вкладку **"Auth"**
   - Выбрать тип **"Bearer Token"**
   - Вставить скопированный токен
   - ИЛИ в вкладке **"Headers"** добавить:
     - **Key:** `Authorization`
     - **Value:** `Bearer <скопированный_токен>`

**Что необходимо заскринить:**
1. ✓ URL: `http://localhost:3000/auth/login`
2. ✓ Метод POST и заголовки
3. ✓ Тело запроса с email и password
4. ✓ HTTP статус 200 OK
5. ✓ Тело ответа с `access_token` и данными пользователя

### Сценарий 3: Получение профиля текущего пользователя

#### Описание
Проверка функции получения данных профиля аутентифицированного пользователя. Демонстрирует использование JWT токена в защищенных запросах.

#### Предусловия
- Приложение запущено
- Пользователь аутентифицирован (см. Сценарий 2)
- Получен и сохранен JWT токен

#### Инструкция по воспроизведению

**Шаг 1: Создать новый GET запрос**

1. В Postman создать новый запрос (Ctrl+T)
2. Выбрать метод **GET**
3. Ввести URL: `http://localhost:3000/users/me/profile`

**Шаг 2: Добавить авторизацию**

**Способ 1: Через вкладку Auth (рекомендуется)**

1. Перейти на вкладку **"Auth"**
2. В выпадающем списке "Type" выбрать **"Bearer Token"**
3. В поле "Token" вставить сохраненный токен из Сценария 2

**Скриншот: Вкладка Auth с Bearer Token**
```
┌─────────────────────────────────────────────────────────────────┐
│ Auth   │ Headers │ Body │ Pre-request Script │ Tests             │
├─────────────────────────────────────────────────────────────────┤
│ Type: [Bearer Token ▼]                                          │
│ Token: [eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...]              │
│                                                                  │
│ ✓ Available Tokens  ☐ Inherit auth from parent                 │
└─────────────────────────────────────────────────────────────────┘
```

**Способ 2: Через вкладку Headers**

1. Перейти на вкладку **"Headers"**
2. Добавить новую строку:
   - **Key:** `Authorization`
   - **Value:** `Bearer <скопированный_токен>`

**Шаг 3: Отправить запрос**

Нажать **"Send"**

#### Ожидаемый результат

**HTTP Статус:** `200 OK`

**Тело ответа:**
```json
{
  "id": 1,
  "email": "testuser@example.com",
  "firstName": "Иван",
  "lastName": "Петров",
  "role": "USER",
  "createdAt": "2026-05-13T10:30:00.000Z",
  "updatedAt": "2026-05-13T10:30:00.000Z",
  "bio": null,
  "avatar": null
}
```

**Что необходимо заскринить:**
1. ✓ URL запроса: `http://localhost:3000/users/me/profile`
2. ✓ Метод GET
3. ✓ Вкладка Auth с выбранным типом "Bearer Token" и токеном

5. ✓ Полное тело ответа с профилем пользователя

### Сценарий 5: Получение списка тем образования

#### Описание
Проверка функции получения списка опубликованных образовательных тем с поддержкой пагинации и фильтрации. Этот запрос не требует аутентификации.

#### Предусловия
- Приложение запущено
- В БД загружены тестовые данные (миграции и seed выполнены)
- Postman открыт

#### Инструкция по воспроизведению

**Шаг 1: Создать новый GET запрос**

1. В Postman создать новый запрос (Ctrl+T)
2. Выбрать метод **GET**
3. Ввести URL: `http://localhost:3000/topics`

**Шаг 2: Добавить параметры запроса (Query Params)**

1. Перейти на вкладку **"Params"** (обычно справа от Headers)
2. Добавить следующие параметры (опционально):

| Key | Value | Описание |
|-----|-------|---------|
| `skip` | `0` | Количество пропускаемых записей (для пагинации) |
| `take` | `10` | Количество возвращаемых записей |
| `search` | `кибер` | Поиск по названию темы (опционально) |

**Скриншот: Вкладка Params**
```
┌─────────────────────────────────────────────────────────────────┐
│ Params  │ Auth │ Headers │ Body │ Pre-request Script │ Tests     │
├─────────────────────────────────────────────────────────────────┤
│ KEY          │ VALUE           │ DESCRIPTION                    │
├──────────────┼─────────────────┼───────────────────────────────┤
│ skip         │ 0               │ Number of topics to skip       │
│ take         │ 10              │ Number of topics to return     │
│ search       │ кибер           │ Search query (optional)        │
└─────────────────────────────────────────────────────────────────┘

URL: http://localhost:3000/topics?skip=0&take=10&search=кибер
```

**Шаг 3: Отправить запрос**

Нажать **"Send"**

#### Ожидаемый результат

**HTTP Статус:** `200 OK`

**Тело ответа:**
```json
{
  "data": [
    {
      "id": 1,
      "title": "Основы кибербезопасности",
      "description": "Введение в кибербезопасность и базовые принципы защиты информации",
      "slug": "basics-of-cybersecurity",
      "isPublished": true,
      "createdAt": "2026-05-01T08:00:00.000Z",
      "updatedAt": "2026-05-01T08:00:00.000Z"
    },
    {
      "id": 2,
      "title": "Фишинг и социальная инженерия",
      "description": "Методы атак через фишинг и способы защиты",
      "slug": "phishing-and-social-engineering",
      "isPublished": true,
      "createdAt": "2026-05-02T09:00:00.000Z",
      "updatedAt": "2026-05-02T09:00:00.000Z"
    }
  ],
  "total": 2,
  "skip": 0,
  "take": 10
}
```

**Проверка параметров:**

- Количество возвращаемых элементов ≤ значению параметра `take`
- Поле `total` содержит общее количество тем
- Все темы имеют статус `isPublished: true`

**Что необходимо заскринить:**
1. ✓ URL с параметрами: `http://localhost:3000/topics?skip=0&take=10&search=...`
2. ✓ Вкладка Params с установленными параметрами
3. ✓ HTTP статус 200 OK
4. ✓ Структура ответа с массивом тем и метаданными пагинации

### Сценарий 7: Получение материалов темы

#### Предусловия
- Приложение запущено
- Известен ID темы (обычно ID = 1)
- Тема содержит связанные материалы

#### Инструкция по воспроизведению

**Шаг 1: Создать новый GET запрос**

1. В Postman создать новый запрос (Ctrl+T)
2. Выбрать метод **GET**
3. Ввести URL: `http://localhost:3000/topics/1/materials`

**Шаг 2: Отправить запрос**

Нажать **"Send"**

#### Ожидаемый результат

**HTTP Статус:** `200 OK`

**Тело ответа:**
```json
{
  "materials": [
    {
      "id": 1,
      "title": "Введение в кибербезопасность",
      "type": "ARTICLE",
      "url": "https://example.com/intro",
      "description": "Базовые понятия кибербезопасности",
      "createdAt": "2026-05-01T08:00:00.000Z"
    },
    {
      "id": 2,
      "title": "Видеоурок: Защита паролей",
      "type": "VIDEO",
      "url": "https://youtube.com/watch?v=...",
      "description": "Как создавать и хранить надежные пароли",
      "createdAt": "2026-05-01T09:00:00.000Z"
    }
  ],
  "total": 2

```

**Проверка целостности:**

- Каждый материал содержит обязательные поля (id, title, type, url)
- Поле `type` содержит валидные значения (ARTICLE, VIDEO, LINK и т.д.)

### Сценарий 17: Обработка ошибок - Конфликт при регистрации (дублирующийся email)

#### Описание
Проверка механизма обработки ошибок при попытке регистрации с email, который уже зарегистрирован в системе. Система должна вернуть статус 409 (Conflict).

#### Предусловия
- Приложение запущено
- Пользователь с email `testuser@example.com` уже зарегистрирован
- Postman открыт

#### Инструкция по воспроизведению

**Шаг 1: Создать новый POST запрос**

1. В Postman создать новый запрос (Ctrl+T)
2. Выбрать метод **POST**
3. Ввести URL: `http://localhost:3000/auth/register`

**Шаг 2: Установить заголовки**

1. Перейти на вкладку **"Headers"**
2. Убедиться:
   - **Key:** `Content-Type`
   - **Value:** `application/json`

**Шаг 3: Добавить данные существующего email в Body**

1. Перейти на вкладку **"Body"**
2. Выбрать **"raw"** и **"JSON"**
3. Ввести данные:

```json
{
  "email": "testuser@example.com",
  "password": "DifferentPassword123!",
  "firstName": "Петр",
  "lastName": "Иванов"
}
```

**Шаг 4: Отправить запрос**

Нажать **"Send"**

#### Ожидаемый результат

**HTTP Статус:** `409 Conflict` или `400 Bad Request`

**Тело ответа:**
```json
{
  "statusCode": 409,
  "message": "Email already registered",
  "error": "Conflict"
}
```

**Или:**

```json
{
  "statusCode": 400,
  "message": "Email already exists",
  "error": "Bad Request"
}
```

**Проверка целостности:**

- Статус код должен быть `409` или `400`
- Сообщение об ошибке должно указывать на проблему с email

**Что необходимо заскринить:**
1. ✓ URL регистрации
2. ✓ Метод POST с заголовками
3. ✓ Body с дублирующимся email
4. ✓ HTTP статус 409 или 400
5. ✓ Сообщение об ошибке
